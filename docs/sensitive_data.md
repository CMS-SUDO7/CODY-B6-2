# 민감정보 처리 점검

2026-10-08 Windows / Python 3.14.4에서 검사했습니다. 기존 구현은 기본 이메일과 PASSWORD 값은 가렸지만 passwd/pwd/비밀번호, 하이픈·숫자 이름, 인증 헤더, 여러 줄 비밀번호 등에서 누락이 있었습니다. safety.py의 처리 범위를 보완하고 [전체 테스트 34개가 통과](evidence/sensitive-test-results.txt)했습니다. 실제 비밀번호·개인정보·유효한 API 키를 검증 자료로 사용하지 않았으며 외부 API 호출은 없습니다.

| 비밀번호 이름 | PASSWORD/password/dbPassword/passwd/pwd/passphrase/DB_PASSWORD_2 | 값 마스킹, diff의 추가·삭제 줄 모두 검사 |
| 한글 이름 | 비밀번호/패스워드/암호/비밀 키/인증키/토큰 | 값 마스킹 |

| 출력 예산 | max_tokens / maxOutputTokens의 숫자 | 값 유지, 인증 토큰과 구분 |

## 처리 흐름 검증

기본 안전 모드에서 status/diff/reason/test를 가린 다음 길이를 제한하고 프롬프트와 REST JSON을 만듭니다. 테스트는 실제 generate 함수가 만드는 POST 본문을 urlopen 직전에 검사합니다. API 키 헤더는 인증에 필요하며 생성 프롬프트에 넣지 않습니다. 네트워크 응답만 모의 자료로 대체했습니다.

별도로 dry-run 출력, AI가 반환한 PR 제목·요약·Why/What/How to Test, HTTP 오류 메시지에서 가짜 비밀값이 남지 않는지 검사했습니다. 200줄을 넘는 비밀번호 블록도 길이 제한 전에 가렸습니다. 일반 JSON 이웃 필드와 출력 토큰 예산 숫자를 보존하는 검증도 있습니다.

재현 명령: `python -m unittest discover -s tests -v`. 새 마스킹 테스트는 [tests/test_safety.py](../tests/test_safety.py)에 있습니다. 로그의 테스트 수는 메서드 수이고 각 테스트 안에서 여러 입력 조합도 검사합니다.

## 적용 대상과 한계

이 도구는 AI 전송 자료와 터미널 출력을 마스킹합니다. 로컬 원본·Git index·기존 커밋·GitHub 원본을 수정하지 않습니다. 따라서 원본 코드에 비밀값을 넣은 채 git add/commit/push하면 별도로 노출될 수 있습니다. 이미 GitHub에 올린 값은 이 함수를 고쳐도 과거 커밋에서 사라지지 않습니다.

이름이나 알려진 형식이 없는 임의 비밀 문자열은 자동으로 식별할 수 없습니다. 여러 표현식으로 나눈 값, 임의 인코딩, 지원하지 않는 문법 등은 추가 탐지가 필요하며 모든 개인정보·비밀값의 완전한 보호를 보장하지 않습니다. 인용부호가 닫히지 않으면 남은 전체 자료를, 인용되지 않은 할당 값이나 인증 헤더는 줄의 나머지를 보수적으로 가리므로 요약 맥락이 줄어들 수 있습니다. 새 패턴을 추가할 때는 누락과 오탐을 함께 검사합니다.

`--no-safe-mode`는 원문 전송을 허용하는 옵션입니다. 해당 모드에서도 최종 출력은 마스킹하지만 이미 전송한 입력을 되돌릴 수는 없습니다. 실제 자료는 기본 안전 모드를 유지하고 dry-run 결과를 확인합니다.
